## Phase 1: Core Mental Model

### One-Sentence Purpose

This project recognizes human emotions from egocentric wearable data by fusing three modalities -- first-person video, eye tracking, and cardiac PPG signals -- through frozen pretrained encoders and learnable fusion architectures, evaluated against a 9-class emotion classification benchmark (EgoEmotion, NeurIPS 2025, ETH Zurich).

### The Core Loop

```
Raw wearable signals (video, gaze+pupils, PPG)
  --> Frozen pretrained encoders (VideoMAE V2, PatchTST, Papagei)
  --> Cache embeddings to disk (.pt files)
  --> Linear projection to shared 256-dim space
  --> Fusion module (7 architectures to compare)
  --> Multi-task classification head (emotion + soft labels + VAD)
  --> LOSO cross-validation across 40 subjects
  --> Weighted F1 as primary metric
```

### The Key Bet

**Frozen encoder + lightweight fusion.** Rather than fine-tuning large encoders end-to-end (expensive, overfitting-prone with 40 subjects), the project pre-extracts embeddings with frozen pretrained models and trains only the fusion layers. This makes experiments fast (<1 GB VRAM), repeatable, and allows rapid iteration across 7 fusion architectures. The bet is that the pretrained representations are rich enough that the fusion layer alone can learn cross-modal interactions sufficient for emotion recognition.

## Phase 2: Data Flow Trace

### Stop 1: Raw Data (EgoEmotion Dataset)

**WHAT:** 40 subjects wearing Meta Project Aria glasses, each performing emotion-eliciting tasks across two sessions (A and B). Three concurrent signals are recorded.

```
IN:  Subject 005's raw recording session
OUT: Per-subject directory with:
     - pov.mp4           (egocentric video, 10 FPS, ~6 min)
     - gaze_90fps.npy    (gaze x,y coordinates at 90 Hz)
     - pupils_90fps.npy  (pupil diameter L,R at 90 Hz)
     - ppg_ear_125hz.npy (photoplethysmography at 125 Hz)
     - Session_A_*.csv, Session_B_*.csv (emotion labels)
```

**WHY these modalities:** The paper hypothesizes that emotions have observable signatures across visual behavior (what you look at), physiological arousal (pupil dilation, heart rate), and contextual scene content (what's happening in front of you). No single modality captures the full picture -- that's why fusion is the research question.

**THE SHAPE of data:**
- Video: 10 FPS, variable duration per task (~10s to ~60s)
- Eye tracking: 90 Hz, 4 channels (gaze_x, gaze_y, pupil_left, pupil_right)
- PPG: 125 Hz, 1 channel
- Labels: 9 discrete emotions -- Amused, Content, Excited, Awe, Neutral, Fear, Sad, Disgust, Anger

**WHAT COULD GO WRONG:** Different sample rates (10/90/125 Hz) mean temporal alignment is critical. The `task_times.npy` file provides segment boundaries at 90 Hz, and `SegmentExtractor` (`src/data/segments.py:54-69`) handles rate conversion for non-90Hz signals.

### Stop 2: Segmentation (`src/data/segments.py`)

**WHAT:** `SegmentExtractor` reads `task_times.npy` (a dict mapping subject -> task -> [start, end] at 90Hz) and slices raw signals into per-task segments. There are two segmentation schemes:

1. **Task-based segments** (variable length): one segment per task, used by `run_experiment.py`
2. **10-second fixed segments** (paper-matched): non-overlapping 900-sample windows at 90Hz (= 10 seconds), yielding 2,678 segments across all subjects, used by `run_experiment_10s.py`

```python
# src/data/segments.py:37-52 — Task-based segmentation
def get_segments(self, subject_id: str) -> list[dict]:
    subject_tasks = self.task_times[subject_id]
    session_a_start = subject_tasks["session_A"][0]
    segments = []
    for task_name, (start, end) in subject_tasks.items():
        if task_name in ("session_A", "session_B"):
            continue
        segments.append({
            "task_name": task_name,
            "start_idx": start - session_a_start,
            "end_idx": end - session_a_start,
            "subject_id": subject_id,
        })
    return segments
```

```
IN:  subject_id = "005", task_times.npy
OUT: [{"task_name": "task_1", "start_idx": 0, "end_idx": 5400, "subject_id": "005"}, ...]
     Each segment represents one emotion-eliciting task
```

**WHY two schemes:** Task-based segments match the natural structure of the experiment (one emotion per task) but have variable length. The paper uses fixed 10s windows for reproducibility and comparability. The 10s scheme uses `ce_hardlabel_manifests/dataset_manifest.csv` with 2,678 rows.

**WHAT COULD GO WRONG:** `load_signal()` at line 54-69 handles the 90Hz->125Hz rate conversion for PPG. An off-by-one in the conversion (`int(start_90hz * 125 / 90)`) could misalign PPG with eye tracking by up to 1 sample.

### Stop 3: Frozen Encoders

Three pretrained encoders transform raw signals into embedding vectors. All are frozen (no gradient updates).

#### 3a: Video -- VideoMAE V2 (`src/encoders/video_mae.py`)

```python
# src/encoders/video_mae.py:18-46
class VideoMAEV2Encoder(BaseEncoder):
    MODEL_NAME = "OpenGVLab/VideoMAEv2-Base"  # 86M params, embed_dim=768

    def __init__(self) -> None:
        super().__init__(embed_dim=768)
        config = AutoConfig.from_pretrained(self.MODEL_NAME, trust_remote_code=True)
        self.model = AutoModel.from_pretrained(self.MODEL_NAME, config=config, trust_remote_code=True)
        self.freeze()

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        if x.dim() == 5 and x.shape[2] == 3:
            x = x.permute(0, 2, 1, 3, 4)  # [B,T,C,H,W] -> [B,C,T,H,W]
        return self.model(x)  # Returns [B, 768] directly (mean-pooled internally)
```

```
IN:  [B, 3, 16, 224, 224] — 16-frame clips at 224x224 RGB
OUT: [B, 768] per clip — mean-pooled ViT patch embeddings
     For a 10s segment (~100 frames at 10fps): ~6 clips → [6, 768]
```

**WHY VideoMAE V2:** Self-supervised video pretraining (dual-masking on UnlabeledHybrid-1M) captures temporal dynamics without emotion-specific labels. V2 improved over V1 with better pre-training methodology. 768-dim is the standard ViT-Base embedding size.

**WHY 16-frame clips:** VideoMAE's architecture uses tubelet_size=2, processing 16 frames as 8 temporal tokens. A 10s video at 10fps = 100 frames = ~6 non-overlapping 16-frame clips.

#### 3b: Eye Tracking -- PatchTST (`src/encoders/patchtst.py`)

```python
# src/encoders/patchtst.py:16-86 (key parts)
class PatchTSTEncoder(BaseEncoder):
    def __init__(self, num_channels=4, patch_len=45, stride=22, d_model=128,
                 n_heads=4, n_layers=3, seq_len=900, dropout=0.1):
        # num_patches = (900 - 45) / 22 + 1 = 39 patches
        self.patch_proj = nn.Linear(patch_len, d_model)      # 45 -> 128
        self.channel_embed = nn.Embedding(num_channels, d_model)  # distinguish gaze_x/y, pupil_L/R
        self.transformer = nn.TransformerEncoder(...)         # 3 layers, 4 heads

    def forward(self, x):  # x: [B, 900, 4]
        patches, B, C, num_patches = self._create_patches(x)  # [B*4, 39, 45]
        h = self.patch_proj(patches) + pos_embed + channel_embed
        h = self.transformer(h)                                # [B*4, 39, 128]
        h = h.view(B, C, num_patches, -1).mean(dim=1)        # average across 4 channels
        return h                                               # [B, 39, 128]
```

```
IN:  [B, 900, 4] — 10 seconds of gaze_x, gaze_y, pupil_L, pupil_R at 90Hz
OUT: [B, 39, 128] — 39 temporal patch tokens, each 128-dim
```

**WHY PatchTST:** Time-series transformer with channel-independent patching. Each of the 4 channels (gaze x/y, pupil L/R) is patched independently with a stride of 22 samples (0.24s), giving 39 temporal patches. Channel embeddings let the transformer distinguish which signal it's processing.

**WHY self-supervised pretraining:** `PatchTSTPreTrainer` (`src/encoders/patchtst.py:89-145`) uses masked patch prediction (40% mask ratio) -- predict masked patches from surrounding context. This learns temporal patterns in eye behavior before seeing emotion labels.

**WHAT COULD GO WRONG:** If `checkpoints/patchtst_pretrained.pt` doesn't exist, the encoder uses random weights (see Finding 2 in code review). This was flagged as a critical bug.

#### 3c: PPG -- Papagei (`src/encoders/papagei.py`)

```python
# src/encoders/papagei.py:37-105 (key parts)
class PapageiEncoder(BaseEncoder):
    # ResNet1DMoE: 18 blocks, 3 experts, Conv1d backbone
    def __init__(self, weights_path="weights/papagei/papagei_s.pt"):
        self.model = ResNet1DMoE(in_channels=1, base_filters=32, n_block=18, n_experts=3, n_classes=512)
        # Load Nokia Bell Labs pretrained weights, strip 'module.' prefix
        self.freeze()

    def forward(self, x):  # x: [B, T, 1] or [B, 1, T]
        outputs = self.model(x)   # Returns (class_emb, moe1, moe2, backbone_emb)
        return outputs[3]         # [B, 512] — backbone features before projection head
```

```
IN:  [B, 1, 1250] — 10 seconds of PPG at 125Hz, z-score normalized, single channel
OUT: [B, 512] — global backbone embedding (already pooled by the ResNet)
```

**WHY Papagei:** Foundation model for PPG signals (Nokia Bell Labs, ICLR 2025). Pre-trained on large-scale cardiac data, captures heart rate variability features relevant to arousal/valence. Uses Mixture of Experts for efficiency.

**WHY `outputs[3]` not `outputs[0]`:** `outputs[3]` is the backbone embedding before the projection head -- richer representation than the contrastive projection head output.

**KEY DIFFERENCE:** PPG produces a single [512] vector (no temporal tokens), while video produces [T, 768] and eye tracking produces [39, 128]. This asymmetry is why fusion design is non-trivial -- some modalities have sequence structure, one doesn't.

### Stop 4: Embedding Cache (`src/encoders/extract.py`)

**WHAT:** `EmbeddingExtractor` runs each frozen encoder once, saves outputs as `.pt` files to disk. All subsequent training loads only from cache.

```python
# src/encoders/extract.py:87-118
def extract_all(self, encoder_name, encode_fn, device, config_hash):
    cache_valid = self.validate_cache(encoder_name, config_hash)
    for subj in subjects:
        for idx, seg in enumerate(segments):
            if cache_valid and self.is_cached(encoder_name, subj, idx):
                continue  # Skip if cache valid AND file exists
            embedding = encode_fn(subj, seg)
            self.save_embedding(encoder_name, subj, idx, embedding.cpu(), metadata=seg, config_hash=config_hash)
```

```
Cache layout:
data/embeddings_10s/
  video_mae_v2/{subject}/segment_{idx:04d}.pt    → {"embedding": [T, 768], "metadata": {...}, "config_hash": "..."}
  patchtst_eye/{subject}/segment_{idx:04d}.pt     → {"embedding": [39, 128], ...}
  papagei_ppg/{subject}/segment_{idx:04d}.pt      → {"embedding": [512], ...}
```

**WHY cache:** VideoMAE V2 inference on 2,678 segments is slow (~hours on GPU). Caching enables rapid iteration on fusion architectures without re-running encoders. Cache invalidation uses SHA-256 hash of config to detect stale embeddings.

**WHAT COULD GO WRONG:** The code review (Finding 3) found that when `validate_cache()` detects a hash mismatch, it previously still skipped files that existed on disk. This was fixed -- the extraction loop now checks `cache_valid AND is_cached()` (line 107), so stale caches get regenerated.

### Stop 5: Modality Projection (`src/fusion/projector.py`)

**WHAT:** Each modality's embedding has a different dimensionality. `ModalityProjector` applies a learned linear layer to map each to a common dimension (d_common=256).

```python
# src/fusion/projector.py:8-16
class ModalityProjector(nn.Module):
    def __init__(self, embed_dims: dict[str, int], d_common: int):
        self.projectors = nn.ModuleDict(
            {mod: nn.Linear(dim, d_common) for mod, dim in embed_dims.items()}
        )
    def forward(self, inputs):
        return {mod: self.projectors[mod](x) for mod, x in inputs.items()}
```

```
IN:  {"video": [B, T, 768], "eye_tracking": [B, 39, 128], "ppg": [B, 512]}
OUT: {"video": [B, T, 256], "eye_tracking": [B, 39, 256], "ppg": [B, 256]}
```

**WHY 256:** Design choice in `configs/base.yaml:21`. A smaller common space acts as an information bottleneck, forcing the projection to retain only the most task-relevant features. 256 is standard for lightweight fusion.

**CONNECTIONS:** The projector is wrapped inside `ProjectedFusion` (`scripts/run_experiment.py:150-187`), which also handles the sequence/pooled compatibility logic -- if a fusion module doesn't support sequences (`supports_sequence_input = False`), projected 3D tensors are mean-pooled to 2D with mask-aware averaging before reaching the fusion module.

### Stop 6: Fusion Modules (`src/fusion/`)

All 7 fusion architectures implement `BaseFusionModule`, accepting `(embeddings: list[Tensor], modality_ids: list[str], masks: list[Tensor|None])` and returning a single `[B, d_out]` fused representation.

#### 6a: EarlyFusion (`src/fusion/early.py`)
Simplest baseline. Concatenate all modality vectors, pass through a 3-layer MLP with BatchNorm.
```
[B, 256] + [B, 256] + [B, 256] → concat [B, 768] → MLP → [B, 256]
```
**Does NOT support sequences** -- inputs must be pooled to 2D first.

#### 6b: MidFusion (`src/fusion/mid.py`)
Per-modality MLP refinement, then concatenate + cross-modal MLP. Like early fusion but with modality-specific processing first.
```
video → MLP → refined_v, eye → MLP → refined_e, ppg → MLP → refined_p
→ concat [B, 768] → cross-modal MLP → [B, 256]
```
**Does NOT support sequences.**

#### 6c: LateFusion (`src/fusion/late.py`)
Each modality gets its own full branch (Linear+ReLU+Dropout+Linear). Outputs are averaged or weighted-averaged. This is decision-level fusion -- each branch makes an independent judgment.
```
video → branch_v → [B, 256]  }
eye   → branch_e → [B, 256]  } → weighted average → [B, 256]
ppg   → branch_p → [B, 256]  }
```
**Does NOT support sequences.** Learns per-modality importance weights with `nn.Parameter`.

#### 6d: PerceiverIOFusion (`src/fusion/perceiver_io.py`) -- **Supports sequences**
Based on DeepMind's Perceiver IO. Uses 32 learnable latent vectors that cross-attend to all modality tokens concatenated together, with modality embeddings to distinguish source.
```
All tokens: [B, T_total, 256] (video T + eye 39 + ppg 1 tokens)
Latents: [B, 32, 256] (learnable)
→ 2 layers of: cross-attention(latent←tokens) + self-attention(latent) → [B, 32, 256]
→ mean pool → project → [B, 256]
```
**WHY:** Perceiver IO can handle arbitrary-length, heterogeneous inputs without quadratic attention over all tokens. The latent bottleneck compresses information.

#### 6e: QFormerFusion (`src/fusion/qformer.py`) -- **Supports sequences**
Based on BLIP-2's Q-Former. 16 learnable query tokens, 6 layers, cross-attention every 2 layers. Uses post-norm (BERT-style) residual connections.
```
Queries: [B, 16, 256] (learnable, fewer than Perceiver's 32)
KV: [B, T_total, 256] (all modality tokens)
→ 6 layers: self-attn + (cross-attn every 2nd layer) → [B, 16, 256]
→ mean pool → project → [B, 256]
```
**WHY:** Q-Former is more parameter-efficient than Perceiver IO (fewer queries, sparser cross-attention).

#### 6f: HEALNetFusion (`src/fusion/healnet.py`) -- **Supports sequences**
Hybrid Early-fusion Attention Learning Network. A shared memory bank (16 slots) is iteratively updated by each modality in turn, via per-modality cross-attention.
```
Memory: [B, 16, 256] (learnable init)
→ For each layer:
    → For each modality:
        memory = cross_attn(memory, modality_tokens) + cross_ffn + self_attn + self_ffn
→ mean pool → project → [B, 256]
```
**WHY:** HEALNet processes modalities sequentially within each layer, naturally handling missing modalities (just skip that modality's update). The shared memory acts as a running summary.

**KEY DESIGN:** Missing modality handling (line 152-158): if fewer modalities are provided than `num_modalities`, the extra blocks simply don't fire and the memory stays unchanged.

#### 6g: MultimodalLegoFusion (`src/fusion/multimodal_lego.py`) -- **Supports sequences**
The most complex architecture. Per-modality LegoBlocks with Fourier-domain cross-attention. 6 modes:

- **Merge modes** (independent processing, combine at end):
  - `merge-sum`: Add complex latents in Fourier domain
  - `merge-product`: Multiply complex latents
  - `merge-mean`: Average complex latents
  - `merge-harmonic`: Weighted harmonic mean of magnitudes, average of phases

- **Fuse modes** (sequential processing):
  - `fuse-stack`: Pass latent through each modality's block sequentially
  - `fuse-weave`: Interleave single-depth passes from each block

```python
# LegoBlock core: Fourier-domain cross-attention (src/fusion/multimodal_lego.py:235-264)
for i in range(self.depth):
    if self.frequency_domain:
        fft_l = torch.fft.fft(latent, dim=self.fourier_dim)
        l_real = fft_l.real
        x_real = torch.fft.fft(x, dim=self.fourier_dim).real
    latent = self.cross_attns[i](l_real, context=x_real) + l_real
    latent = self.cross_ffs[i](latent) + latent
    if i < self.depth - 1:  # IFFT except last iteration
        latent = torch.fft.ifft(torch.complex(latent, l_imag)).real
```

**WHY Fourier domain:** The paper argues that cross-attention in frequency domain captures periodic/rhythmic patterns better (relevant for heart rate, gaze oscillations). The imaginary component is tracked for phase-preserving reconstruction.

**WHY this is the best performer:** fuse-stack (F1=0.81) passes the latent sequentially through all modalities, so each block can refine based on what previous modalities contributed. This creates a deep iterative refinement, but it only achieves 0.81 on task-based segments, not on the paper-matched 10s segments.

### Stop 7: Multi-Task Head & Loss (`src/tasks/`)

**WHAT:** Three simultaneous prediction tasks from the fused representation:

```python
# src/tasks/heads.py:8-20
class MultiTaskHead(nn.Module):
    def __init__(self, d_fused=256, num_emotions=9, num_vad=3):
        self.emotion_head = nn.Linear(d_fused, 9)   # Hard label classification
        self.soft_head    = nn.Linear(d_fused, 9)   # Soft label distribution
        self.vad_head     = nn.Linear(d_fused, 3)   # Valence/Arousal/Dominance regression
```

```
IN:  [B, 256] fused representation
OUT: {"emotion_logits": [B, 9], "soft_logits": [B, 9], "vad_pred": [B, 3]}
```

**Multi-task loss** (`src/tasks/losses.py:38-84`):
```
L = lambda_ce * WeightedCrossEntropy(emotion_logits, hard_label)
  + lambda_kl * KL_Divergence(soft_logits, soft_distribution)
  + lambda_vad * (1 - CCC(vad_pred, vad_true))
```

**WHY multi-task:** The three label types capture different aspects of emotion:
- **Hard CE:** Which discrete emotion? (primary metric: weighted F1)
- **Soft KL:** How ambiguous is this emotion? (distribution over 9 classes)
- **CCC loss:** How does this map to continuous valence/arousal/dominance?

Multi-task training acts as regularization -- the shared fusion representation must support all three views simultaneously.

**NaN safety:** Zero-lambda losses are skipped entirely (lines 63-82) to prevent NaN from unused heads.

### Stop 8: LOSO Training (`src/trainer/fusion_trainer.py`)

**WHAT:** Leave-One-Subject-Out cross-validation across 40 subjects. For each fold: 38 train, 1 val (early stopping), 1 test.

```python
# src/trainer/fusion_trainer.py:273-328
def run_loso(self, all_data, subject_ids):
    for i, test_subj in enumerate(subject_ids):
        val_subj = subject_ids[(i + 1) % len(subject_ids)]
        train_subjects = [s for s in subject_ids if s not in (test_subj, val_subj)]
        # Deep-copy model for each fold (line 54)
        fusion_model = copy.deepcopy(self.fusion_model).to(self.device)
        task_head = copy.deepcopy(self.task_head).to(self.device)
```

```
Per fold:
  38 subjects (~2,500 samples) → train
  1 subject (~67 samples)      → val (early stopping, patience=10)
  1 subject (~67 samples)      → test

  Optimizer: AdamW, lr=1e-4
  Scheduler: CosineAnnealing over max_epochs=100
  Class weights: inverse frequency from training set (handles class imbalance)
  Best checkpoint: restored from best val weighted_f1
```

**WHY deep-copy:** Each fold starts from scratch with fresh random initialization of the fusion+head parameters. This prevents information leakage between folds.

**WHY LOSO (not k-fold):** Emotion expression is highly subject-dependent. LOSO ensures the test subject is never seen during training, measuring true generalization to new individuals.

**Collation** (`fusion_trainer.py:223-263`): The inline collate function handles three cases:
1. 0D/1D tensors → simple stack
2. 2D with uniform sequence length → simple stack
3. 2D with variable length → pad + boolean mask

This is critical for mixing modalities with different token counts (video has ~6 clips, eye has 39 patches, PPG has 1 token).

## Phase 3: Architecture Decisions

| Decision | Why | Tradeoff | Could Revisit If... |
|----------|-----|----------|---------------------|
| **Frozen encoders, cached embeddings** | Fast iteration, low VRAM (<1GB), no encoder overfitting on 40 subjects | Cannot adapt encoder features to task; ceiling on representation quality | Fine-tuning VideoMAE shows gains (separate script exists) |
| **d_common = 256** | Information bottleneck forces relevance; matches standard lightweight fusion | May lose subtle features from 768-dim video | Experiments plateau at current accuracy |
| **Multi-task (CE + KL + CCC)** | Regularization from multiple supervision signals; captures ambiguity | More complex training, 3x label engineering | Single-task CE matches or beats multi-task (see ablation results) |
| **LOSO evaluation** | Gold standard for subject-independent generalization | 40 folds = 40x training time; high variance per fold | Sample size grows; fixed train/test splits become viable |
| **PatchTST for eye tracking (custom)** | Channel-independent patching handles heterogeneous signals (gaze vs pupil); self-supervised pretraining | Custom model requires pretraining; not a published architecture | Pretrained time-series foundation model becomes available |
| **Papagei backbone (`outputs[3]`)** | Richer than projection head; captures more cardiac features | 512-dim vs 512-dim (same size, different information) | Task-specific fine-tuning of PPG encoder |
| **Fourier-domain cross-attention (MM-Lego)** | Captures periodicity in physiological signals; mathematically principled merge | More complex, harder to debug; imaginary tracking adds overhead | Simpler fusion matches performance |
| **`supports_sequence_input` flag** | Clean separation: non-sequence modules get pooled inputs automatically | Implicit pooling can hide bugs (see code review Finding 1) | All fusion modules support sequences natively |

## Phase 6: Gaps Map (Fragile Spots / Watch List)

### 1. Task-Segment vs 10s Performance Gap (Critical)

Task-segment experiments reach F1=0.81 while 10s experiments reach F1=0.23. This ~3.5x gap is the most important open question. Possible causes:
- Task segments are much longer (variable, up to 60s) giving more signal
- 10s windows may split emotional episodes awkwardly
- The Lego fuse-stack result (0.81) uses a different paradigm (pretrained blocks + zero-shot merge)
- The code review found sequence collapsing bugs that were partially fixed

**Where to investigate:** Compare the data shapes reaching the fusion module in both paths. Add logging to `ProjectedFusion.forward()` to verify tensor shapes are 3D for sequence-aware modules.

### 2. Sequence Collapsing in Data Loaders (Partially Fixed)

The code review (Finding 1 & 4) identified that both `run_experiment.py` and `run_experiment_10s.py` collapsed `[T, D]` embeddings to `[D]` before fusion. The `normalize_loaded_embedding()` function was added to preserve singleton sequences, and `ProjectedFusion` now handles mask-aware pooling only for non-sequence modules.

**Status:** Fix is in place for 10s path. Verify by checking that `PerceiverIOFusion`, `QFormerFusion`, `HEALNetFusion`, and `MultimodalLegoFusion` actually receive 3D inputs during a live run.

### 3. PatchTST Pretrained Weights Requirement

If `checkpoints/patchtst_pretrained.pt` is missing, extraction scripts should now raise `FileNotFoundError`. But this should be verified -- a silent fallback to random weights would silently corrupt all eye-tracking embeddings.

### 4. Hardcoded Constants

- `NUM_CLASSES = 9` in linear probe script -- would break if emotions change
- `EMBED_DIM = 768` in linear probe -- coupled to VideoMAE V2 specifically
- `SEQUENCE_ENCODER_DIRS = {"video_mae_v2", "patchtst_eye"}` in `run_experiment.py:35` -- must be updated if a new sequence encoder is added
- `encoder_map = {"video": "video_mae_v2", "eye_tracking": "patchtst_eye", "ppg": "papagei_ppg"}` in `run_experiment_10s.py:243` -- duplicated across scripts

### 5. No Confusion Matrix or Per-Class Metrics in Reports

The reporting system tracks aggregate weighted F1 and CCC but doesn't save confusion matrices or per-class F1. For a 9-class problem with severe imbalance, knowing which emotions are confused is critical for debugging.

### 6. Dead Code: `CustomTopologyFusion`

`CustomTopologyFusion` (pairwise/hierarchical/gated topologies) in `multimodal_lego.py:549-635` is defined but has no corresponding config or entry point. It's documented as "alternative baselines" but never wired up.

### 7. MM-Lego Two-Phase Paradigm Is Separate

The best-performing method (Lego fuse-stack, F1=0.81) uses `scripts/run_lego_experiment.py` with pretrained blocks + SLERP classifier head merging. This is a completely different paradigm from the standard fusion pipeline and isn't exercised by `run_experiment.py` or `run_experiment_10s.py`. The high F1 may not be directly comparable.

### 8. Papagei Repo Path Is Hardcoded

```python
# src/encoders/papagei.py:26
_PAPAGEI_REPO = Path(__file__).resolve().parents[3] / "papagei-foundation-model"
```
This assumes the papagei repo is at `../../../papagei-foundation-model` relative to the encoder file. Breaks on any non-standard directory layout.

## Questions to Explore Further

1. **Why is the 10s performance so much worse than task-segment?** Is it the shorter window, different segmentation, or a remaining bug in the data pipeline?
2. **Are sequence-aware fusion modules actually receiving sequences?** Add shape logging to confirm during a live 10s run.
3. **Is the Lego fuse-stack F1=0.81 reproducible and fair?** Does the pretrained-block paradigm have an unfair advantage (seeing labels during block pretraining)?
4. **What does the confusion matrix look like?** Which emotions are being confused? Are positive emotions (Amused/Content/Excited/Awe) reliably separated from negative ones?
5. **How much does each modality contribute?** Run ablations with 1 and 2 modalities to measure marginal contribution.
6. **Can fine-tuning VideoMAE close the gap to the paper baseline?** The fine-tuning script exists but results aren't in the registry yet at competitive levels.
7. **Is PatchTST pretraining actually helping?** Compare frozen-random vs frozen-pretrained PatchTST embeddings.
